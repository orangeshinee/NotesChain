# 平替预演报告（自造旧目录）

日期：2026-11-01  
目的：在没有拿到真实 Silver Bullet 目录之前，先用一个**故意做旧、布局不统一**的语料，验证 PRD 10.1「现有目录原样启动」的相关能力。

> **这不是真实目录验收**。真实目录里可能还有 SB 专属 frontmatter、插件生成的查询块、特殊文件命名等，仍需按 `docs/verify.md` 在真机上跑一遍。本报告证明的是「机制上走得通」。

## 怎么跑

```powershell
node tools/legacy-corpus.js .demo/legacy-notes   # 生成旧风格语料
pwsh -File tools/legacy-check.ps1                # 起服务 + 断言 + 比对文件哈希
```

`legacy-corpus.js` 刻意造出这些「不规整」：

| 特征 | 目的 |
| --- | --- |
| 平铺的 `2026-10-01.md`（靠 `# 日期` 标题判定） | 验证文件类型判定的「内容兜底」 |
| `Daily/2026-10-03.md` 另一种布局 | 验证不强制 `YYYY/MM/` |
| `2026/10/2026-10-04.md` 标准布局 | 验证主规则 |
| `Projects/供应链.md`（不在 raw/ 下） | 普通笔记也要参与待办/标签/搜索 |
| `raw/供应链.md` + `raw/子目录/供应链.md` | 同名裸名冲突 |
| 带 `todo:` 的旧写法 | 迁移清单 |
| ````query` 查询块 | SB 专属语法当普通文本 |
| `../assets/a.png` 与 `assets/b.png` | 图片双轨两种写法 |
| 带 BOM 的文件、带 CRLF 的文件 | Windows 编辑器常见编码 |
| 带 frontmatter 的日记（\---\ 开头） | SB 常见结构，标题判定要能跳过 frontmatter |
| 代码块里的 `- [ ]` | 不该被当成待办 |

## 从预演里确认的行为

1. **不强制目录结构**：平铺、`Daily/`、`YYYY/MM/` 三种布局同时存在，日记都认出来了，普通笔记没被误判
2. **SB 语法不报错**：`query` 块原样当文本，不执行、不破坏
3. **只认 `- [ ]`**：`todo:` 不混进待办，而是进迁移清单
4. **双轨图片**：旧文件里的相对写法与根基准写法都能显示，不用改文件
5. **同名不炸**：`raw/` 下两份同名笔记只告警，路径形式仍可精确指向
6. **不改写既有文件**：这是「平替」最硬的一条，预演通过
