# NotesChain 性能测试报告（v0.1）

日期：2026-11-01  
对应 PRD：第 8 章「非功能要求与性能测法」

## 结论

PRD 第 8 章除内存外的各项指标**全部达标**；内存为 **29 MB**，落在 v0.5 放宽后的参考目标（< 50 MB）之内。

| 指标 | PRD 标准 | 实测 | 结果 |
| --- | --- | --- | --- |
| 冷启动（进程启动 → 索引就绪） | < 1 秒 | **0.30 秒** | ✅ |
| 空载内存（工作集） | 参考目标 < 50 MB | **29.0 MB** | ✅ |
| 待办汇总 `/api/todos` | < 3 秒 | **104 ms** | ✅ |
| 全文搜索 `/api/search`（中文词） | 无硬指标 | **8–18 ms** | ✅ |
| 标签树 `/api/tags` | 无硬指标 | **3 ms** | ✅ |
| 日程视图 `/api/schedule?range=week` | 无硬指标 | **1 ms** | ✅ |
| 重建索引 `/api/index/rebuild` | 无硬指标 | **118 ms** | ✅ |

## 语料

由 `tools/gen-corpus.js` 生成，规格对齐 PRD 第 8 章：

- **1000 个 `.md`**：730 个日记文件（两年按天）+ 270 个 `raw/` 主题笔记
- **总量 18.8 MB**，最大单文件 19.4 KB（远低于 200 KB 上限）
- **待办**：未完成 3460 条，另有 730 条已完成，合计约 4200 条
- 日记含日程段、嵌套待办、SQL 代码块；主题笔记含标签与正文

生成命令：

```powershell
node tools/gen-corpus.js .demo/perf-notes
```

## 测法

1. **冷启动**：记录进程启动时刻，轮询启动日志出现 token 行的时刻（索引在打印前构建完成），差值即冷启动耗时。
2. **空载内存**：启动后空闲 5 秒，读进程工作集（不含浏览器与短命 git 子进程）。
3. **接口延迟**：登录拿到 Cookie 后，每个接口连续请求 3 次取中位数。
4. **重建索引**：`POST /api/index/rebuild` 单次计时。

## 已知边界与风险

1. **`/api/todos` 是 O(n) 串行化**：首轮用「每文件 700 条待办」的极端语料（19 万条）压测时，该接口耗时 4.7 秒、内存 141 MB。按 PRD 规格（约 5 千条）是 104 ms，但若真实使用中长期不清理已完成待办、待办总量上万，这个接口会成为瓶颈。后续可加：分页 / 只返回前 N 条 + 总数、或前端分页拉取。
2. **索引常驻全文**：内存 ≈ 语料大小 × 1.5。20 MB 语料约 29 MB；若笔记库涨到 200 MB，内存会到 300 MB 量级。需要时再改成「只存倒排 + 行偏移，正文按需读盘」。
3. **网络盘未测**：云桌面上 `git status` 与文件监听在网络盘上的表现须单独测（PRD 第 8、10.3 节）。
4. **git 提交路径**：本机沙箱限制导致应用内 `git commit` 无法验证（见 README 的说明），提交耗时未计入本报告。
